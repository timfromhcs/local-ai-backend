# Release plan: v0.5.0 → v1.0 (local · cloud · web · EXE · GitHub · README)

Researched 2026-11-03. Loop: pick the next unchecked item, change one thing, run the gates,
commit through a PR, tick the box. No item is done without a command that proves it.

## 0. Research that shapes this release

| Finding | Consequence here |
|---|---|
| CSP is the only header that actually constrains XSS; `script-src` needs an explicit allowlist, and CDN modules must be listed by origin | add a real CSP to `web/vercel.json`, verify against production with Playwright |
| `'unsafe-inline'` is acceptable for styles but not for scripts; inline JSON-LD is data, not executed | CSP: strict `script-src` + `'unsafe-inline'` only for `style-src` |
| OpenSSF passing badge = documented security policy, quick start, licence, contribution path | add `SECURITY.md`, `CONTRIBUTING.md`, keep the quick start measured |
| READMEs that convert start with *why*, then install, then verify, then troubleshooting; badges are navigation, not decoration | restructure README: Why → Quick start → Verify → Troubleshooting |
| Attestation verification (`gh attestation verify`) belongs next to the checksum step | already added in the README, keep it in the verify block |

## 1. Definition of "next stable" (v0.5.0)

A release is stable when **all** of these are true:

- [x] `pytest -m "not real"` green on Ubuntu and Windows (currently 236)
- [x] web gate (SEO, i18n parity, assets) + accessibility audit green
- [x] secret scan clean, `pip-audit` clean, SBOM generated and attached
- [x] `localai-gateway --self-test` passes on a machine with no models and no network
- [x] production page: CSP present, 0 console errors, 0 CSP violations, 8 sections
- [x] README: why, install, verify, troubleshoot, security, contribution — no unmeasured claim
- [ ] two consecutive green runs on `main` before the tag

## 2. Work items

### W1 — EXE self-test (local surface)
`localai-gateway --self-test` builds the app in-process, calls `/healthz`, `/v1/models`,
`/doctor`, `/v1/placement` and `/openapi.json`, prints a table and exits 1 on any failure.
No port is opened, so it works in CI and on a locked-down machine.
Gate: unit test with a temp registry; the EXE smoke test in CI runs it too.

### W2 — CSP and headers (cloud/web surface)
`web/vercel.json`: `Content-Security-Policy` with
`default-src 'self'`, `script-src 'self' https://esm.run https://cdn.jsdelivr.net`,
`style-src 'self' 'unsafe-inline'`, `img-src 'self' data:`,
`connect-src 'self' http://127.0.0.1:8090 https://huggingface.co https://*.huggingface.co https://cdn-lfs.huggingface.co`,
`worker-src 'self' blob:`, `object-src 'none'`, `frame-ancestors 'none'`.
Gate: `check-web.mjs` asserts the policy exists and has no `unsafe-eval`; Playwright checks the
production response header and that the page still works.

### W3 — README restructure (GitHub surface)
Why → Quick start → Verify a release → Surfaces → Measured → Architecture → Demo → Bench → MCP →
Troubleshooting → Limits → Roadmap. Every number links to `docs/perf-log.md`.
Gate: a test asserts the required sections exist and that no "TODO" ships.

### W4 — SECURITY.md and CONTRIBUTING.md (GitHub surface)
Security policy with a private reporting path and a scope list that admits what is *not* a
vulnerability here (no auth, localhost by design). Contributing: the gates, the commit shape,
the PR ruleset, the no-model-files rule.
Gate: files exist, linked from README, and the test suite checks the links.

### W5 — Design review (better-design)
Run `get-review-rules`, `check-comprehension` and the a11y audit; fix every critical/serious
finding. The page keeps its existing token set — this is a review, not a redesign.
Gate: audit green, no serious finding left, screenshots at 390 and 1440.

### W6 — Release and loop
Bump to 0.5.0, tag after two green runs, publish EXE/wheel/sdist/SBOM, confirm GHCR.
Gate: `gh release view` shows 5 assets; `gh attestation verify` documented.

### W7 — After v0.5.0 (v1.0 candidates)
Publishing tokens (npm/PyPI), physical-phone pass, 20+ RSI pairs then a 1.5B run, OpenAPI client
generation. These stay in the long-term roadmap; they are not blockers for 0.5.0.

## 3. Loop mechanics

Every cycle: one item above, its gate, a PR through the ruleset, this file updated with the
evidence. The hourly wake prompt drives the loop; a cycle that cannot finish leaves the item
unchecked and explains why in the log, rather than marking it done.
