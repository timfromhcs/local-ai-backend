# Plan: LocalAI Gateway v1.0 — one engine, every surface

Researched 2026-11-03/08. Supersedes the earlier plans for distribution and surfaces.
Rule of this repo: a claim without a command that proves it is a bug.

## 0. SOTA research (what is true now)

### Browser inference runtimes
| Runtime | Format | Acceleration | Notes (measured/reported) |
|---|---|---|---|
| **wllama** (llama.cpp → WASM) | **GGUF** | WASM, optional WebGPU | Same format as our gateway; loads any GGUF from Hugging Face; lowest browser memory in the LlamaWeb paper (geomean 49 % below WebLLM, 41 % below Transformers.js); one of two runtimes that survived an iPhone 15 Pro |
| WebLLM (MLC) | MLC compiled | WebGPU | Curated catalogue, OpenAI-compatible API, small default context (1–4 k) |
| Transformers.js | ONNX | WebGPU / WASM | Best ONNX catalogue; heavier memory; our current demo path |
| Chrome Prompt API | built-in | device | Only Chrome/Edge desktop, model not portable |

Decision: **wllama for the real in-browser path** (GGUF, same weights as local), keep ONNX as a
fallback tier and for the embedding lab. "No demo" means: the browser runs an actual quantised model
and answers a real prompt, with no server in the loop.

### Containers
Vercel runs **any Dockerfile** as a container Function (OCI image, Fluid compute, autoscaling),
with the normal Function limits and **no GPU**. Multi-container projects use `services` + rewrites.
So a Vercel container can host the **gateway API and MCP**, but not a 27B model. Local Docker
(PC/NAS) and GHCR images carry the real inference; the phone gets inference through the browser.

### Packaging
- PyPI: build with `python -m build`, publish via **Trusted Publishing** (OIDC, no token).
- npm: publish a thin launcher/wrapper package (downloads the release binary), not the binary itself.
- GHCR: `docker/build-push-action` with `docker/metadata-action`, multi-arch where the base allows.

## 2. Work packages (v1.0)

### WP1 — API contract (stable)
- Freeze `/v1/models`, `/v1/chat/completions`, `/healthz`, `/doctor`, `/v1/bench`.
- JSON error schema + OpenAPI snapshot test; versioned via `X-LocalAI-Version`.
- Acceptance: contract tests in CI fail on any breaking change.

### WP2 — Real browser inference (wllama, GGUF)
- Third mode "GGUF im Browser": model presets (LFM2.5-350M, Qwen2.5-0.5B, Qwen2.5-1.5B), OPFS cache,
  streaming, cancel, token counters, honest speed display.
- Low precision allowed: q2_k/q4_k_m presets, labelled as such.
- Acceptance: Playwright loads a 350M model and gets a non-empty answer, offline after first download.

### WP3 — Device adaptation
- Breakpoints 320/390/768/1024/1440/2560, `dvh` layout, safe-area insets, touch targets ≥ 44 px,
  virtual-keyboard handling for the composer, landscape chat layout, `prefers-reduced-motion`.
- Acceptance: no horizontal overflow at 320 px; composer stays visible with the keyboard open.

### WP4 — Containers
- `api/Dockerfile` (python:3.13-slim, non-root, healthcheck, no models), `docker-compose.yml`,
  `.dockerignore`; GHCR publish workflow with tags (`latest`, semver, sha).
- Vercel container service for the API shell; honest statement that it cannot run the model.
- Acceptance: `docker build` + `docker run` + `/healthz` locally; GHCR image digest recorded.

### WP5 — Packages
- PyPI wheel with `localai-gateway` entry point (already), Trusted Publishing workflow.
- npm package `@hcsmedia/localai-gateway` whose `postinstall` fetches the matching release binary
  (checksum verified) and whose CLI forwards args.
- Acceptance: `npm pack` installs clean in a temp dir; `python -m build` wheel installs in a fresh venv.

### WP6 — MCP server for the gateway
- `localai-gateway-mcp`: tools `list_models`, `chat`, `bench`, `doctor`, `load_model`, `unload`.
- Acceptance: official SDK client lists the tools, a real `chat` call returns a completion.

### WP7 — Release engineering v1.0
- CI matrix + web gate + docker build + package build + MCP probe; tag `v1.0.0` publishes EXE, wheel,
  sdist, npm tarball, GHCR image, checksums.
- README rewritten around the stable contract; loop of "measure → fix → re-run" until two consecutive
  green runs on `main` and a tagged release that a fresh machine can install from.

## 3. Order and gates

1. WP1 → WP2 → WP3 (web must be real before it is packaged).
2. WP4 → WP5 (containers and packages only consume the frozen contract).
3. WP6 (MCP) → WP7 (release).
Each WP ends with its own gate; v1.0 is tagged only when all seven gates are green twice in a row.

## 4. Honest constraints

- Vercel has no GPU: the container serves API/MCP, not the 27B model.
- A phone browser runs ≤ 1.5B q4 comfortably; 27B stays on the PC.
- GGUF in WASM is single-threaded without COOP/COEP; we do not enable those headers because they break
  CDN imports (documented trade-off, measured in WP2).
- No code signing yet; SmartScreen warning stays documented.
- "Stable v1" means the API and install paths are frozen and tested — not that the models got better.

## 5. Loop

Every WP: measure → smallest fix → re-run gate → log the number in `docs/perf-log.md` or the WP
section here. No phase is marked done from intent.
